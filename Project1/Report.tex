\section{Introduction}

The sport of mixed-martial arts (MMA) is widely regarded as one of the most unpredicatable- and dynamic sports one can spectacte. A sudden knockout, freak injury or a mistake giving way to a submission, 
it's a sport where anything, at any moment, can happen. When each bout is equally probable to be a controlled, one-sided domination as it has being an explosive war of violence and unpredicatability,
the question becomes: can an outcome of such an event even be predicted? Let alone consistently? \par

The UFC (Ultimate Fighting Championship) is currently the largest professional MMA organization with an extensive record of fights spanning across its 30+ years of existence. With such a 
long and lustrious history, finding a suitable dataset was not a a difficult task and \href{https://www.kaggle.com/datasets/anthonysz/ufc-fight-data-2026/data}{Kaggle, UFC Fight Data - 2026} 
provided just that.\par

With records dating back to March 2010 all the way to May of this year, it covers over 7000 fights and includes 57 features that describe each fighters stats., physical attributes and betting odds, and more.
The set also includes a binary classifier on the winning figher (whether the figher in the red corner won or lost), which works as a great predictor feature.\par

Given this predictor feature we want to take note of the given baseline: the red figher has a win rate of 58\% against blue's 42\%, which is a significant gap.\par

With this benchmark, the main goal of this project then becomes two-fold:  
\begin{itemize}
    \item Develop a model that can outperform the simple majority class baselines and accurately predict a UFC fight based purely on statistcal differences between the fighters.
    \item See which attributes/features contribute the most to a outcome and by how much of a margin.
\end{itemize}

\subsubsection{Outliers \& Missing Data}

\paragraph*{The \_return Columns}
The values of the red\_return and blue\_return columns reflect the payout a \$1 bet would return. Including them would cause target leakage since they tell the 
model exactly who won (loser's return being 0) and in turn lead to a 100\% model prediction rate accuracy; something we obiviously wanted to avoid.

\paragraph*{Stance Outliers}
We noticed in the red\_stance and blue\_stance columns that there were a few rows with faulty classifications and missing data ("Switch " with a trailing space and "Unknown"),
that needed to be excluded. We also found one other classification called "Open Stance", which describes an opposite stance matchup, which was only found in the blue\_stance column. 
Since we already have the three main stances ("Orthodox", "Southpaw" and "Switch") it becomes a redundant categorical value and only creates conflict.

\paragraph*{Weight Class Outliers}
In the column weight\_class there we found the value "Catch Weight" which describes fights where one or both fighters missed their target weight and therefore fought outside 
one of the 12 regulartory weight classes. This is by definition an outlier to the standard procedure of an MMA bout and should therefore be excluded.

\paragraph*{Outliers in \_diff Columns}
In the rounds\_diff column we found one extreme outlier where the value was over 440. We excluded this due to it being an impossible data value when
looking at either fighters records (i.e. total fights).\\
In the reach\_diff column there is a single outlier where the reach difference was over 186 caused by one of the fighters reach being measured 0 cm.
This is an obivious error caused by a missing data value so we naturally excluded it.

\paragraph*{Logistic Regression}
Why did we choose logistic regression as our baseline for accuracy?.

Pros:
\begin{itemize}
    \item Since our data is split between \_diff features and other features, and the \_diff features are numeric, that is what logistic regression is built for. So for example, each unit of reach advantage shifts the odds of red winning by some amount.
    \item Another reason for using logistic regression is it's fast to train and does not take a lot of setup.
\end{itemize}

Cons:
\begin{itemize}
    \item A limitation of logistic regression is that it assumes a relatively simple relationship between the features and the log-odds of the outcome. It also does not automatically capture interactions between features. or example, maybe reach advantage has different effects based on what weight class the fight is in.
\end{itemize}

Why include it: To establish a baseline for comparison, we will be comparing them to a simple logistic regression model.

\paragraph*{Random Forest}
The reasons we chose random forest for one of our models are.

\begin{itemize}
    \item Handles the mix of numeric \_diff and categorical features without needing scaling, and works well with on-hot encoded categorical features.
    \item A major benefit of random forests is that they can capture non-linear relationships and interactions automatically, for example, the takedown advantage matters a lot more when the weight difference between the fighters is larger.
\end{itemize}

\paragraph*{XGBoost}
The reasons we chose XGBoost for one of our models are.

Pros:
\begin{itemize}
    \item Like random forests, XGBoost can capture non-linear relationships and interactions. However, instead of averaging many independently trained trees, XGBoost builds trees sequentially, with each new tree attempting to correct errors made by the previous trees. Since our data set is not too big the training time for the models is not too long.
    \item Captures non-linear relationships and interactions like random forest, but often extracts more predictive power from the same features because each new tree learns from the previous ones.
\end{itemize}
Cons:
\begin{itemize}
    \item There are a lot of hyperparameters to tune, and if you don't tune them well the model can be prone to overfitting.
    \item Requires one-hot encoding for categorical features, which can cause the numbers of features to blow up quite quickly.
\end{itemize}

Why include it: XGBoost provides a useful comparison with random forest because both can capture non-linear relationships and interactions, but they use different ensemble approaches.

\paragraph*{CatBoost}
The reasons we chose CatBoost for one of our models are.

Pros:
\begin{itemize}
    \item Handles categorical features natively, instead of one-hot encoding, this is very useful since we have a lot of categorical features.
    \item CatBoost can make use of categorical features directly and can capture relationships between categorical variables, such as red_stance and blue_stance. This has a big impact on real fight analysis,For example, the interaction between red_stance and blue_stance could potentially be relevant to fight outcomes.
\end{itemize}
Cons:
\begin{itemize}
\item Is quite similar to XGBoost. It can be slower to train than some of the other models, particularly when using more complex settings.
\end{itemize}

Why include it: this gives a good way to test whether the native category handling matters, and a good way to find that out is compare XGBoost vs CatBoost.
